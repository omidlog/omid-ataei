# Schemas

JSON Schema draft-07 is used so Ajv can validate records without a draft-2020 vocabulary dependency.

| Schema | Records |
| --- | --- |
| `question.schema.json` | Interview questions |
| `answer.schema.json` | Ledger entries |
| `mascot-state.schema.json` | The 90 catalog rows. `status` is the artwork lifecycle (`defined`, `pending`, `created`, `reviewed`, `approved`, `published`, `deprecated`). Optional `emotion`, `use_cases`, `outfit`, `accessories`, `animation_refs`, `license`, and `artwork[]` variants (`id`, `stage`, `angle`, `intensity`, `outfit`, `accessories`, `asset_id`, `preview_asset_id`, `animation_refs`, `status`, `version`, `license`). `brand:validate` adds lifecycle rules; `brand:migrate` converts pre-0.2 statuses. |
| `asset.schema.json` | Asset manifest rows. Optional `model_use` (`not_allowed`, `local_only`, `external_allowed`); absent means `not_allowed`. |
| `task-context.schema.json` | The `task_context` pack (`brand-os/task-context/v1`). Not a stored record: it is the read-only output contract of the Task Context Engine (`docs-internal/TASK_CONTEXT.md`), checked against this schema in `tests/task-context.test.ts`. |
| `visual-dna.schema.json` | The `visual_dna` result (`brand-os/visual-dna/v1`). Not a stored record: read-only reference verdicts (approved, withheld, missing, changed) with checksum, rights and `model_use`, metadata only (`docs-internal/VISUAL_DNA.md`). Checked in `tests/visual-dna.test.ts` and `tests/visual-dna-agent.test.ts`. |
| `coach-result.schema.json` | One Strategic Coach analysis (`brand:coach`). Advisory and derived: `authority` is always `derived_advice`, `authorizes` is always empty, and the record carries ids, closed-vocabulary codes and explanation text only — never an answer value, a quotation, a restricted value or a score. The authoritative validator is the Zod schema in `packages/brand-core/src/coach/model.ts`; `tests/coach-core.test.ts` checks real results against both so they cannot drift. |
| `runtime-post-manifest.schema.json` | One drafted social post from the Brand Runtime (`brand-os/runtime-post-manifest/v1`): SVG file, sha256, the `task_context` sources it cites by id and revision, assets with their effective `model_use` (`sent_to_model` is always false), and checks reported by the layers that own them. Output contract, not a stored brand record (`docs-internal/BRAND_RUNTIME.md`). |
| `runtime-batch.schema.json` | The batch summary of one `social_batch` run (`brand-os/runtime-batch/v1`): pack digest, posts, set checks, Coach and Assurance results, `advisory: not_tested`, `authorizes: []`. Checked in `tests/runtime-social-batch.test.ts`. |
| `production-readiness.schema.json` | The production-readiness projection (`brand-os/production-readiness/v1`, fixes pack PR-E): a separate view over a `task_context` pack that never changes the pack's own `readiness`. `production_ready` is `ready` only when no deterministic rule blocks; every check names its rule owner, input, verdict and whether it blocks; taste and persuasion are `needs_human_review` / `not_tested`; `authorizes: []`. Output contract, not a stored record (`docs-internal/BRAND_RUNTIME.md`). Checked in `tests/production-readiness.test.ts`. |
| `acceptance-report.schema.json` | The acceptance report (`brand-os/acceptance-report/v1`, fixes pack PR-F): what `brand:acceptance` ran for the four journeys, PASS / FAIL / NOT_TESTED per check with evidence of ids, counts, codes and checksums only; a case is PASS only when every check passed; `authorizes: []`. Output contract, not a stored record (`docs-internal/ACCEPTANCE.md`). Checked in `tests/acceptance-harness.test.ts`. |

Token files are checked by the DTCG compiler in `@brand-os/design-tokens`, which is stricter than a generic object schema. Color values in this template are sRGB objects with a 6-digit `hex`. Components are optional and, when present, must match the hex.
